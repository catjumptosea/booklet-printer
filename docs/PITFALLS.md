本文件记录 Booklet Printer 中已经实际出现过、容易重复踩坑的问题。它用于补充 `AGENTS.md`：

- `AGENTS.md` 只写长期规则和入口索引。
- 本文件记录具体现象、根因、修复原则、验证方式和回归风险。
- 新问题修复后，如果它可能再次出现，应在这里追加一条记录。

## 册子视图出现白色槽位，页面内容像被白色遮住

- 状态：已修复
- 现象：册子视图中，部分跨页只在上、下两条缝隙附近露出内容，中间主要区域为白色；纸张视图显示正常。双页文档、混合文档和单页文档的册子视图都可能受影响。
- 适用范围：`FlipView` 中需要裁切、拼接、定位书脊锚点或兼容不同 PDF 页面尺寸的预览场景。
- 根因：旧逻辑先在 canvas context 上执行 `translate` / `clip`，然后把同一个已经带变换状态的 context 交给 pdf.js 的 `page.render()`。pdf.js 在绘制时会重写或接管目标 context 的变换，导致经 pdf-lib 重新嵌入后的分层 Form XObject 页面被推到画布之外，槽位只剩白色底。
- 修复原则：不要把已经预先变换或裁切过的 canvas context 直接交给 pdf.js 绘制。应先用普通 viewport 把源 PDF 页完整渲染到离屏 canvas，再按裁切、旋转和书脊锚点规则，用 `drawImage` 合成到目标 canvas。裁切页和非裁切页都应走同一条渲染路径。
- 修复原则：如果图片源在进入 page-flip 前已经通过 `preloadImage` 加载，就不要保留会造成白色 loader 帧的异步状态分支；加载状态需要同步注入并持续重绘。
- 验证方式：
  - 用真实扫描型 PDF 分别测试单页、双页、混合文档。
  - 统计每个跨页左右半区的 dark / nonWhite 像素比例，确认除尾部补白页和预览虚拟页外，没有整半页纯白。
  - 回归 A6 + 书脊间距 30mm、A5 + 书脊间距 30mm 等布局组合。
  - 检查全屏高清 `updateFromImages()` 路径。
  - 执行生产构建，并用 standalone `dist` 做一次预览验证。
- 回归风险：后续优化渲染性能时，如果又尝试把预裁切 context 直接交给 pdf.js，白页问题会复发。`PageCanvas` 路径没有预变换，所以纸张视图正常，不能只凭纸张视图通过就判断册子视图正常。
- 相关文件：`src/components/FlipView.jsx`、`src/components/PageCanvas.jsx`

## 册子视图退出全屏后，点击右侧变成向前翻页

- 状态：已修复
- 现象：在册子视图中进入全屏再退出后，点击书页右侧没有向后翻，反而退回前一跨页；在退出的瞬间点击最容易复现。
- 适用范围：`FlipView` 的全屏切换，以及任何会改变 `.flipbook-stage` / `.stf__canvas` 尺寸但不会重建 `PageFlip` 实例的布局变化。
- 根因：`page-flip` 在 `Render.boundsRect` 中缓存书页区域，`updateFromImages()` 只替换图片集，不会清除或重新计算该缓存。退出全屏时 DOM 很快缩回普通尺寸，但缓存仍保留全屏的 `1346×952`；点击坐标继续按旧的全屏宽度判断左右半区，视觉上的右页于是落入内部左半区，方向被反转。
- 修复原则：全屏进入和退出时必须刷新 `page-flip` 的布局边界，不能只调用 `updateFromImages()`。对退出后立刻发生的第一次点击，还要在点击捕获阶段按当前 DOM 尺寸刷新一次布局，再交给 `page-flip` 判断方向。
- 验证方式：
  - 进入全屏，等待高清图片替换完成后退出。
  - 退出后立即点击书页右侧，页码必须前进；再点击左侧，页码必须后退。
  - 在点击前后读取 `PageFlip.getRender().getRect()`，确认缓存宽高已从全屏尺寸恢复到当前舞台尺寸。
- 回归风险：后续优化全屏或图片替换时，如果只更新设置或图片而不刷新布局缓存，点击方向反转会复发。由于箭头按钮和书页点击走不同入口，不能只验证底部翻页按钮。
- 相关文件：`src/components/FlipView.jsx`
